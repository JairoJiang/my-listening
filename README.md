# My Listening · 电脑 / iPhone 合并版

只上传这个文件夹的内容，即可用同一个网址提供电脑和移动端界面。无需构建、无需安装依赖。原来的两个文件夹是备份，不需要上传。

## 自动识别

- iPhone、Android、iPad 默认加载移动布局；也识别以桌面模式访问的常见 iPad，以及窄屏触控设备。
- 普通电脑默认加载电脑布局，缩窄电脑窗口不会自动切换成手机模式。
- 移动布局保留安全区、底部七按钮和键盘弹出时的笔记框适配；时间轴采用与电脑版相同的紧凑行高。
- 页面首次加载时决定布局，横竖屏旋转不会重新加载音频。
- 特殊设备可能识别不准，可在右上角“⋯ → 界面”选择自动识别、移动端或电脑端。
- 手动切换会重新加载页面，并尝试恢复本机保存的上次材料及进度。选择尽量保存在当前浏览器。

## 移动端拇指操作区

左上并排为上一个 / 下一个标记，左下为添加；右上并排为上上个 / 下下个标记，右下为删除；播放居中。图标比原移动端放大约 30%，双排操作区域高约 126px，加上时间、倍速栏及安全区，整体向上扩展。网页无法精确保证物理 3 厘米，各手机屏幕显示尺寸会有差异。电脑版底栏保持原排列。

时间轴标记使用固定大小的红色小旗（旗面 11×9px）。旗杆高低错开，所有行（包括没有标记的行）的标记区固定为 48px，电脑与移动端一致；标记层间距 24px，进度控件高 32px。超过两层时仅在标记区域内部上下滚动，不撑高整行、不改变时间轴宽度。点击小旗仍可跳转并编辑笔记，原有标记数据无需迁移。

## 历史材料与自动恢复

## 笔记列表与 15 天回收

笔记浮窗采用简洁显示：只显示“时间点＋前 15 个词的单行摘要”、删除（回收区为恢复）、展开和关闭按钮；详情窗只显示全文与关闭按钮。正常情况下不显示标题或操作说明，发生错误时仍显示必要提示。窗口高度依据上方材料标题与底部控制区间的可用空间调整，超出的列表与全文在窗内滚动。

PC 鼠标移入笔记图标自动打开；从图标移入列表或详情窗时继续显示，移出这三个区域约 250ms 后自动隐藏，便于点击试听和展开。手机保持点击打开、点击 × 关闭。通过菜单打开的已删除笔记窗口不随悬停关闭。

电脑和手机的底部播放键上方有笔记图标。电脑鼠标悬停即可打开，手机点击打开。历史笔记显示为进度页面上方的非模态悬浮窗，底边始终在底部控制区之上；右上角 × 关闭，不锁定背景滚动或底部按钮。打开、关闭及展开详情不会暂停音频。

每项只显示前 15 个词的单行摘要，窄屏自动省略，不换成第二行。点击笔记跳转原时间并自动播放，列表窗口保持打开；点击末尾“展开”在另一个小窗查看全文，不跳转、不打断试听。没有对应节点的笔记显示红色，原节点删除后仍可试听。跨材料时从本地材料库载入音频，文件不可用会提示重新导入。浏览器若阻止异步载入后的自动播放，可直接点击仍然可用的底部播放键。

删除节点只删除节点，不再删除笔记。笔记列表的“删除”将内容移入“⋯ → 历史笔记”的已删除悬浮窗。点击恢复将它放回笔记列表，但不会重新添加节点；同一时间已有不同笔记时会提示，避免覆盖。编辑笔记并保存空内容也按删除处理。兼容旧的 #notes / #deleted-notes 链接，但正常打开窗口不改变网址。

已删除笔记保留 15×24 小时，从删除时间计算；到期不可恢复。页面打开时、回到前台及运行期间每分钟检查并清除到期记录。网页关闭时无法执行后台清理，到期数据会在下次打开时实际清除。日期判断使用设备时间；不要人为调整时间。未删除的笔记不会因 15 天规则过期。旧版已经被彻底删掉的笔记无法追回。

所有记录仍是当前网站、当前浏览器的本地数据，不是云备份。清理网站数据或系统回收空间可能导致丢失。

## 材料恢复

导入音频后，文件本身存入当前浏览器的 IndexedDB 材料库，不上传服务器。下次打开自动载入最后一次材料，恢复播放位置、倍速、标记、笔记和每行时长；出于浏览器播放限制，需手动点播放。

右上角“⋯ → 历史材料”按最近打开时间列出材料，点击即可切换，无需重新选文件。同名、同大小、同修改时间的原文件再次导入不会重复新增。旧版已丢失的音频无法追回，升级后需要重新导入一次；旧标记仍在当前网站存储中时会继续读取。

播放进度约每秒保存，暂停、跳转、切换材料及页面转入后台时也保存。强制退出可能损失最后一小段进度。保存失败会持续显示提示。笔记仍需点击“保存笔记”提交。

## 上传 GitHub Pages

1. 打开你的 GitHub 仓库，上传本文件夹内的全部文件到根目录。不要只上传 index.html。
2. 根目录应有 index.html、app.js、library.js、note-history.js、shortcuts.js、layout.js、style.css、iphone.css、manifest.webmanifest。README.md 可一并上传。新增 note-history.js 不可遗漏。
3. Settings → Pages，选择 Deploy from a branch、main、/(root)，保存。
4. 等待部署完成，用 Pages 提供的同一个网址访问：电脑显示电脑布局，手机显示移动布局。
5. iPhone 用 Safari 打开该网址，通过分享菜单“添加到主屏幕”。若显示“作为 Web App 打开”，启用它。

如果更新原仓库，请覆盖原先同名文件并补齐新增文件。若把整个合并版文件夹作为子目录上传，则网址后面需要带 /my-listening-unified/。

## 预览与验证

电脑可直接双击 index.html。推荐在此文件夹运行 `python -m http.server 8000 --bind 127.0.0.1`，然后打开 http://localhost:8000 。没有 Python 也可直接双击体验。

同一网址可加查询参数临时指定界面：

- `?layout=mobile`：移动端。
- `?layout=desktop`：电脑端。
- `?layout=auto`：自动识别（覆盖之前记住的选择）。

分别验证音频导入、播放、倍速、单标记/双标记跳转、删除、笔记保存与恢复。手机还需验证竖横屏、滚动到底部和笔记输入时的软键盘。

## 数据与限制

两个布局使用同一套播放与存储逻辑、同一个网站来源下的相同存储键。音频保存在本机浏览器数据库，不上传；正常情况下重新打开无需再次选择原文件。标记按文件名、大小、修改时间匹配，笔记随标记保存。材料较大时需留足设备空间。

同一浏览器同一来源里切换布局可共用数据；这不是跨设备云同步。电脑和 iPhone、Safari 与主屏幕 Web App 不保证共享存储。沿用原网站来源时可读取原先保存的数据；换域名或清理网站数据不会自动迁移。存储失败会在页面提示。

请固定使用同一个主屏幕入口，并使用正常浏览模式。应用会尝试请求持久存储，但是否授予由浏览器决定；iOS 空间不足、清理网站数据或卸载入口等情况下仍可能丢失本地记录，不能保证永久保存。请保留原始音频和重要笔记备份。正式验证材料库请使用 HTTPS 的 GitHub Pages 或 localhost，本地 file:// 的存储行为取决于浏览器。

没有离线启动缓存。主屏幕首次打开或重新加载通常需要网络。尚未发布到 GitHub，也未完成真实 iPhone 验证。
